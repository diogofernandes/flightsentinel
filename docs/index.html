AeroSense

Real-time cockpit anomaly detection. A PySide6 instrument panel that ingests live flight telemetry at 10 Hz, scores each frame with a PyTorch model, and fires alerts when the aircraft deviates from normal envelope.

The problem

A stall approach has a distinct multi-parameter signature: airspeed drops, pitch rises, vertical speed goes sharply negative, all simultaneously. No single parameter threshold catches it reliably. You need to model the normal flight envelope as a whole and flag deviations from it.

Without FlightSentinel

Static per-parameter thresholds. Miss correlated anomalies. False positives in turbulence. No audit trail of events.

With FlightSentinel

ML model scores the joint distribution at 10 Hz. Alerts only on genuine envelope deviation. Every event logged with full parameter context.

How it works

Four stages. Nothing reaches the alert log until it passes through all of them.

01

Stream

A telemetry simulator generates realistic GA aircraft parameters at 10 Hz (altitude, airspeed, pitch, roll, vertical speed) with smooth sinusoidal drift and realistic noise. Every 30 seconds it injects a synthetic stall to exercise the detector. The TCP bridge on port 54399 replaces the simulator with real external data.

02

Score

Each frame is scored by an Isolation Forest trained exclusively on normal cruise data. The algorithm learns the joint distribution of all five parameters. Anomalies are frames that are "hard to isolate" from the rest. The model is wrapped in a PyTorch nn.Module for consistent serialisation and an easy upgrade path to a sequence model.

03

Threshold

Scores above 0.65 trigger an alert, logged on the rising edge only, so a sustained anomaly produces one event, not hundreds. The threshold is a single value in params.py and tunable without touching any other file.

04

Display

A PySide6 window renders amber instrument readouts, a live four-panel pyqtgraph chart, a colour-coded score bar, and a scrollable alert log table. All UI updates happen on the main thread via Qt signals; inference runs in a QThread so the event loop is never blocked.

Architecture

The critical design decision is thread separation. Qt has one rule: never block the main thread. Inference on the main thread causes UI freezes, which is unacceptable at 10 Hz. The solution is a QThread worker that runs the simulator and model, then emits a Qt Signal per frame. The main thread catches it and updates every widget in one pass.

V-cycle mapping

DO-178C certified software requires every requirement to be verified by a test. FlightSentinel applies this principle at demonstrator scale: each design decision traces to a stated requirement and a corresponding test.

Requirement Implementation Verification

External telemetry via TCP

A TCP socket decouples the data source from the application. Swap the simulator for real avionics data, a HIL rig, or another process without changing a line of UI code.
